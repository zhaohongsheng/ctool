## 修复：TBL 表格下载必现失败

- 现象：网页下载工具里 IMG/DOC/MED 正常，勾选 TBL 表格后点「下载选中」全部报失败。
- 根因：`js/tools-download.js` 的页面扫描函数 `scanAllResources()` 里 `pushTable()` 只写入 `csv` / `preview` 等字段，**没有 `url`**；而下载链 `downloadIndices()` 对所有类型统一调用 `downloadUrl(item.url, ...)`，于是 `chrome.downloads.download({url: undefined})` 必抛错。文件里早写好的 `textToDataUrl()` 从未被调用。
- 连带问题：ZIP 打包对表格执行 `fetch(undefined)` 必然失败；`URL.createObjectURL(zip)` 后在 `chrome.downloads.download()` 返回前同步 `revokeObjectURL()`，会让 ZIP 下载被取消；README 承诺的 CSV UTF-8 BOM 实际没写。
- 修复（`js/tools-download.js`）：
  - 新增 `normalizeScannedItems()`：扫描结果回到工具页后，为 table 项补 `data:text/csv;charset=utf-8;base64,...` URL（含 BOM），供展示/复制/打包/兜底共用。
  - 新增 `downloadResource()`：表格优先用同源 `Blob` + object URL 下载（带 BOM），被宿主拒绝时回退 data URL；`await` 下载建立后再延迟 30 秒回收 object URL。非表格资源仍走原 http URL。
  - ZIP 打包表格直接用 `item.csv` 构造 Blob，跳过 fetch；ZIP 下载改为 `await chrome.downloads.download()` 后延迟回收。
  - `copySelection()` 对表格复制 CSV 正文而非 base64；列表渲染改为「N 行 × M 列」摘要（复用 i18n 既有正则）+ CSV 标记，避免把数百 KB data URL 塞进 title/DOM。
- 验证：临时 vm 测试桩模拟扩展环境（tabs/scripting/storage/downloads + DOM），26/26 通过；覆盖根因确认、Blob 主路径、data URL 回退、BOM 字节、ZIP 入包、复制、非表格资源不受影响、revoke 时机。全量源文件与产物 `node --check` 通过；重建 `ctool.user.js`（1433.2 KB / 17 个内联脚本）。
- 限制：油猴单文件版 iframe 的 chrome 垫片故意不提供 tabs/scripting/downloads，网页下载工具整体不可用；本次修复针对扩展版。若需油猴版支持，要另做资源扫描消息桥。
- 未做真实浏览器运行时实测；改动未提交 git；扩展需在 `chrome://extensions` 重新加载。

## 截图返工：长图报错 / 快捷键失效 / 截图时隐藏
- 长图报错根因（多个叠加）：`captureFullPage` 任一帧的 `executeScript` / `captureVisibleTab` 抛错就整张失败；`scrollTo(0,y)` 在 `scroll-behavior:smooth` 站点停在动画中途，帧 y 与画面不符；`compose` 只按 `total` 定画布高度，最后一帧 `y+frameH` 被裁；`toDataURL` 超画布上限返回 `data:,` 未校验；错误信息被吞。
- 修法：逐帧容错（单帧失败跳过、`tabs.get` 检查 active 自动重激活、至少 1 帧才成功、帧字符数 >18M 提前停）、滚动前把 `documentElement.style.scrollBehavior` 临时置 `auto` 并用 `behavior:'instant'`、导出 `stitchPlan()` 按实际帧位置算高度并标记 `capped`、`ensureDataUrl()` 校验 `data:image/`、失败信息带具体原因透传到工具页状态栏。
- 快捷键失效根因：`chrome.commands` 的 `suggested_key` 对「已安装扩展后新增命令」不自动绑定，且 Windows 的 `Alt+Shift` 是系统切换输入语言快捷键，浏览器收不到；`deliverShot` 用 `chrome.tabs.sendMessage` 发给工具箱标签页（扩展页无内容脚本）必然失败被吞，后台也从不广播 ready，已打开的工具箱只能等重新渲染才消费 `pendingShots`。
- 修法：`content.js` 与工具页各自在 capture 阶段监听按键（主通道，不依赖 commands 绑定），默认改 `Ctrl+Shift+7/8/9`；工具页三个按键按钮可录入自定义组合（按 `event.code` + 四个修饰键匹配），`localStorage` + `chrome.storage.local` 双写，内容脚本经 `storage.onChanged` 实时同步；后台 `runtime.sendMessage` 广播 `ctool-screenshot-shot` / `ready`，工具页顶层监听器先 `selectTool('screenshot')` 再 emit；`runCapture` 900ms 同 mode 去重防 commands 与页面监听双触发。
- 新增「截图时隐藏」：后台 `HIDE_FOR_CAPTURE(selectors, hideFixed)` / `RESTORE_AFTER_CAPTURE` 经 `scripting.executeScript` 注入，用 `visibility:hidden` + 备份完整 style（不用 display，长图高度不变），隐藏 `#ctool-floating-host`、`span.ctool-gh-host`、`#ctool-shot-select-host`、用户自定义 CSS 选择器，可选隐藏所有 fixed/sticky 元素；`runCapture` 的 `finally` 无条件恢复。工具页第三张卡提供三个设置，偏好键 `ctoolShotHideSettings`。
- 油猴版：`setSelfVisible(false/true)` 在 `getDisplayMedia` 抓帧前后隐藏/恢复 launcher、overlay 与 GitHub 图标；宿主 keydown 读 `ctoolShotHotkeys` 自定义组合；删掉 iframe 内会丢失用户激活的重复触发。
- 验证：临时 vm 测试桩 58/58 通过（纯函数、长图按帧算高度与高 DPR、隐藏/恢复 DOM 效果、内容脚本热键匹配、工具页录入/保存/重置/cleanup、后台消息桥与去重与广播、i18n 无新增重复、产物 18 内联脚本零外部引用、README 292 行一致）；全量 `node --check`；重建 `ctool.user.js` 1487.3 KB。临时脚本已删除。
